# Шлюз «веб-ChatGPT как модель для OpenCode» — дизайн

Дата: 26.10.2026. Статус: на согласовании.
Заменяет: `2026-10-23-windows-agent-app-design.md` — своё приложение на Tauri больше не делаем.
Рабочее название: **cgpt-gateway**.

## 1. Зачем

Пользователь хочет на домашней Windows-машине продолжить работу, начатую в Codex, через
веб-версию ChatGPT, а не через консоль. Что он хочет видеть, осталось прежним:
- проекты;
- файлы и код;
- правки с разницей «было/стало»;
- подтверждения;
- вопросы карточками;
- скиллы и `AGENTS.md` от Codex.

Решение поменялось. Вместо своего приложения используем готовый агент **OpenCode**: у него есть
интерфейс, инструменты, разрешения и сессии. Подключаем к нему веб-ChatGPT как обычную модель.
Для этого нужен локальный шлюз с OpenAI-совместимым API. Шлюз переводит запросы OpenCode в
сообщения во вкладке ChatGPT через уже проверенный мост cgpt-bridge (расширение Chrome и хост)
и переводит ответы обратно.

Пользователь один, машина личная. API OpenAI не используется: работа идёт по подписке ChatGPT.

## 2. Критерий успеха

В OpenCode на домашней Windows-машине пользователь выбирает модель «ChatGPT Web» и проходит
один этап своего плана в проекте с копированием приложения, со скиллами codex-kit. ChatGPT при
этом:
- читает и ищет по коду;
- правит файлы;
- запускает команды;
- задаёт вопросы.

Перед этим тот же сценарий проходит на Mac на учебном проекте.

## 3. Цели, не-цели, анти-цели

**Цели**
- OpenCode работает с веб-ChatGPT так же, как с моделью по API: инструменты, вопросы, скиллы,
  подагенты.
- Каждая сессия OpenCode живёт в своём чате ChatGPT и продолжается в нём.
- Всё, что уходит в ChatGPT, проходит вычистку секретов.
- Опасные команды из denylist не доходят до OpenCode, какие бы разрешения в нём ни стояли.

**Не-цели**
- Свой интерфейс. Он у OpenCode.
- Свои инструменты, разрешения, хранилище сессий. Они тоже у OpenCode.
- Несколько запросов к ChatGPT одновременно. Шлюз обслуживает их по очереди.
- Показ ответа по мере генерации. На первом этапе ответ отдаётся целиком, когда готов.
- Поддержка других клиентов (Kilo Code и т. п.). Вероятно, заработает сама, но не проверяется.
- MCP-канал, картинки во вложениях, выбор модели ChatGPT из OpenCode.

**Анти-цели** — провал, даже если всё «работает»:
- Сообщение уходит не в тот чат ChatGPT, или две сессии OpenCode смешиваются в одном чате.
- Секреты из файлов или вывода команд уходят в ChatGPT.
- Команда из denylist доходит до выполнения.
- Обычная работа пользователя с ChatGPT в браузере ломается.
- Шлюз доступен с другой машины или без токена.

## 4. Что известно об OpenCode (проверено 26.10.2026, OpenCode 2.1.4)

Получено заглушкой, которая записывала запросы OpenCode (`research/spike-opencode-gateway/`).

- **Запросы.** `POST /v1/chat/completions`, всегда `stream: true` и
  `stream_options.include_usage`. Заголовок `Authorization: Bearer <apiKey из конфига>`. Перед
  работой OpenCode запрашивает `GET /v1/models`.
- **Основной запрос:**
  - системная подсказка около 16 000 символов;
  - 11 инструментов: `glob`, `grep`, `patch`, `question`, `read`, `shell`, `skill`, `subagent`,
    `webfetch`, `websearch`, `execute`. Их JSON-схемы — около 13 000 символов;
  - `max_completion_tokens: 32000`.
- **Заголовок сессии.** OpenCode отдельно просит придумать заголовок: без инструментов,
  `reasoning_effort: "low"`, на `small_model` из конфига.
- **Каждый следующий запрос** содержит всю историю: `system`, `user`, ответ ассистента с
  `tool_calls` в стандартном виде OpenAI и сообщения `role: "tool"` с `tool_call_id` и
  результатом (например, `"Read file a.txt, lines 1-1\n1: alpha"`). Ответ с `tool_calls` в
  SSE-потоке (`finish_reason: "tool_calls"`) OpenCode выполняет сам.
- **Скиллы** OpenCode сам находит в `.agents/skills` и `~/.agents/skills` — там же, где их
  держит Codex. Читает `AGENTS.md`. Разрешения (`allow`/`ask`/`deny`) и вопросы
  (`question`) — его.

## 5. Архитектура

```
OpenCode ──HTTP (127.0.0.1, токен)──► cgpt-gateway ──локальный сокет──► cgpt-bridge-host
                                                                            │ Native Messaging
                                                                            ▼
                                     расширение Chrome ─► своя вкладка chatgpt.com ─► чат сессии
```

**Репозиторий** `bambella667/cgpt-bridge`. Новый крейт `gateway/` — один исполняемый файл на
Rust (моё решение: общий код с хостом и ядром, один бинарник для Windows). Он использует:
- `core/` — вычистку секретов и denylist;
- `protocol/` — кадры и типы сообщений моста.

HTTP-сервер — небольшая синхронная библиотека (`tiny_http`, новая зависимость). CLI `cgpt`
продолжает работать как есть.

**Что остаётся из сделанного в ветке `feat/cgpt-desk-core`** (моё решение):
- **Нужно:** крейт `core` с вычисткой секретов и denylist, включая правила PowerShell и cmd
  после первого круга исправлений.
- **Не нужно** — убирается: протокол v2 (`protocol/src/agent_v2.rs`), граница проекта
  (`workspace.rs`), файловые инструменты и поиск (`core/src/tools/`), лишние пределы из
  `limits.rs`, зависимости `dunce` и `ignore`.

  Всё это у OpenCode, а инструменты выполняются на его стороне.
- **Ветка сохраняется для истории.** Новая работа идёт в ветке от `main`. Недоделанный второй
  круг правок denylist сохраняется коммитом в старой ветке.

## 6. Шлюз

### 6.1. API

- `GET /v1/models` — две модели:
  - `chatgpt-web` — основная;
  - `local-title` — отвечает локально, без ChatGPT.
- `POST /v1/chat/completions` — запросы обслуживаются по очереди, строго в порядке прихода.
  Если ChatGPT занят, запрос ждёт своей очереди; ожидание входит в таймаут запроса.
  - `stream: true` — ответ потоком SSE в формате OpenAI:
    - сразу кусок с `role: "assistant"`;
    - во время ожидания каждые 10 секунд строка-комментарий `: keepalive` (её игнорируют
      SSE-парсеры). Так OpenCode не рвёт соединение по простою, а шлюз замечает обрыв по
      ошибке записи;
    - когда ответ готов — кусок с текстом или с `tool_calls`, затем кусок с `finish_reason` и
      `usage`, затем `[DONE]`.
  - Таймаут хода по умолчанию — 15 минут, задаётся в конфиге (не больше суток). Модель и
    режим ChatGPT шлюз не выбирает: работает та, что выбрана во вкладке.
  - `stream: false` — обычный JSON того же содержания.
- Слушает только `127.0.0.1`. Каждый запрос — с `Authorization: Bearer <токен>`. Без него или с
  чужим — 401.
- Порт, токен и таймаут хода хранятся в конфиге шлюза в папке данных
  (`%APPDATA%\cgpt-gateway\config.json`). При первом запуске токен создаётся случайным.
- Ошибки моста отображаются в ответы OpenAI-формата:
  - **перед каждым ходом шлюз спрашивает мост `status`** (запросы `local-title` — нет). Пока
    ответ не подтвердит текущее расширение, в ChatGPT ничего не уходит, и сессия не меняется.
    Старое расширение не знает адресации и может писать в активную вкладку пользователя
    (приёмка на Mac 27.10: загруженная сборка от 23.10 игнорировала `stop`, `status` и
    адрес чата, запросы просто висели);
  - нет расширения или вкладки (на `status` хост отвечает «расширения нет») → 503;
  - расширение или хост устарели (`status` без ответа расширения — хост ждёт 10 с и отвечает
    `timeout`; `status` или `stop` неизвестны хосту; ответ без адреса чата) → 503
    «Расширение cgpt-bridge устарело: перезагрузите его из extension/dist»; сессия без
    адреса чата не сохраняется как отвеченная;
  - ограничение частоты запросов ChatGPT → 429 с временем паузы и заголовком `Retry-After`
    (секунды до конца паузы);
  - таймаут → 504;
  - не найден ответ на странице → 502.

  Текст ошибки понятен человеку: OpenCode показывает его в интерфейсе.

#### 6.1.1. Ошибки шлюза и повторы клиентов

Правило (решение 43): клиент может повторить запрос, только если сообщение точно не ушло в
ChatGPT. Повтор после отправки — второй ход в чате пользователя. Всё, что могло дойти до
ChatGPT или ждёт человека (вход, вкладка, лимит, остановка, чужой чат), не повторяется. Явно
временное и без отправки (хост перезапускается, очередь не дошла до запроса, своя вкладка занята
прежним ответом) — повторяется.
«Ушло» считается по этому запросу: если ушла хотя бы одна его часть (первая часть длинного
сообщения, вопрос, за которым следует просьба исправить ответ или отказ в вызове), следующий сбой
в нём уже не повторяется. Повтор после обрыва дельты шлёт только её остаток; правило к нему
применяется так же — по тому, ушло ли что-то в повторном запросе.

Как шлюз это сообщает:

- **до первого байта** (ошибка пришла за `first_byte_wait_ms`, 500 мс, или запрос без
  `stream`) — HTTP-статус. Если повторять нельзя, добавлен заголовок `x-should-retry: false`:
  OpenCode 2.1.4 (`isRetryable`) и openai-node смотрят его раньше статуса. Статусы не менялись;
- **в середине потока** (статус 200 уже ушёл) — SSE-событие `{"error": {code, message, type}}`
  и `[DONE]`. Заголовки уже не изменить. Если повторять нельзя, `type` равен
  `invalid_request_error`, иначе `cgpt_gateway`. OpenCode 2.1.4 разбирает событие функцией
  `classifyProviderFailure` без статуса: он смотрит на `code`, `type` и текст. Неизвестная
  ошибка (`UnknownProvider`) повторяется до 10 раз, около 84 секунд. `invalid_request_error`
  даёт `InvalidRequest` — без повтора, но только если раньше не сработала проверка по `code`:
  `code`, в котором есть `unavailable`, и `internal_error` дают `ProviderInternal`;
  `rate_limited` даёт `RateLimit`. Оба повторяются при любом `type`. Поэтому в событии потока
  шлюз пишет `bridge_offline` вместо `extension_unavailable` и `bridge_internal` вместо
  `internal_error` (в HTTP-ответе коды прежние: там решает заголовок). Новые имена не содержат
  `unavailable`, `exhausted`, `rate_limit`, не входят в серверные коды OpenCode и не совпадают с
  его фразами о сбое сервера.

openai-node повторяет HTTP-ответ так: сначала `x-should-retry`, потом 408, 409, 429 и 5xx.
Ошибку в потоке он не повторяет никогда: бросает `APIError`, решает вызывающий код.

| Ошибка шлюза | Когда бывает | Ушло в ChatGPT | Повтор по правилу | HTTP (до потока) | OpenCode 2.1.4, до потока | Событие в потоке | OpenCode 2.1.4, в потоке |
|---|---|---|---|---|---|---|---|

Повторы OpenCode в потоке вопреки правилу (коды `extension_unavailable` и `internal_error`)
закрыты сменой `code` в событии (решение 46). Лимит (`rate_limited`) OpenCode по-прежнему
повторяет один раз: повтор упирается в паузу, ничего не уходит. До потока все строки следуют правилу. Клиенты на
AI SDK (OpenCode 1.x) заголовок `x-should-retry` не читают и повторяют 429 и 5xx до двух раз.

### 6.2. Сессии и чаты

- **Ключ сессии (моё решение).** Заголовок `x-opencode-session-id`, который OpenCode шлёт в
  каждом запросе, включая запросы подагентов. Если заголовка нет — хэш первого сообщения
  пользователя.
- **Что шлюз хранит для сессии:**
  - адрес чата ChatGPT;
  - сколько сообщений истории (кроме `system`) уже доставлено;
  - отпечаток (хэш) каждого доставленного сообщения;
  - хэш системной подсказки и хэш списка инструментов;
  - состояние: `idle` | `in_flight` | `interrupted`.
- **Продолжение.** Если первые N несистемных сообщений запроса совпадают с доставленными по
  отпечаткам, в чат сессии уходят только сообщения после N: результаты инструментов и новые
  сообщения пользователя.
- **Изменилась системная подсказка или инструменты при совпадающей истории (моё решение).**
  Например, сменилась дата, агент build/plan или список скиллов. В тот же чат перед дельтой
  уходит блок «правила и инструменты обновлены» с новой подсказкой и новым списком
  инструментов. Нового чата нет.
- **Смена модели посреди сессии (принято).** Если пользователь переключил сессию OpenCode на
  другую модель, а потом вернулся на ChatGPT Web, начало истории совпадает с доставленным, и в
  чат уходит дельта. Сообщения ассистента в дельту не входят (это ответы самого ChatGPT),
  поэтому текст и вызовы другой модели ChatGPT не видит — только результаты её вызовов и
  сообщения пользователя. Принимаем: случай редкий, а новый пакет стоил бы нового чата.
- **Несовпадение истории** — сжатая OpenCode история, правка прошлого сообщения или неизвестный
  ключ. Шлюз открывает новый чат и отправляет пакет «ввода в курс дела» (6.3).
- **Сжатая история в пакете (моё решение).** Не больше 2 частей по 150 000 символов, то есть
  300 000 символов вместе с подсказкой и инструментами. Без сокращений идут:
  - все сообщения пользователя;
  - текст ассистента;
  - последние 3 результата инструментов.

  Более старые результаты инструментов обрезаются до 2 000 символов. Если всё равно не
  помещается, отбрасываются самые старые ходы с пометкой «N ранних ходов опущено».
- **Большая дельта.** Если дельта длиннее того же предела, её результаты инструментов
  обрезаются так же, как результаты последнего хода в пакете: короткие идут целиком,
  остальные получают равную долю, но не меньше 2 000 символов.
- Сессии хранятся в папке данных шлюза и переживают его перезапуск. Сессии без обращений больше
  7 дней удаляются.
- **Обрыв, таймаут или ограничение частоты посреди хода (моё решение).**
  - Шлюз просит мост остановить генерацию, и сессия получает состояние `interrupted`.
  - Чат не бросается: следующая отправка в него начинается с пометки «предыдущее сообщение
    прервано, ответ на него не нужен; продолжаем с этого места». Затем идут сообщения,
    которых ChatGPT ещё не видел, с последнего доставленного.
  - Если OpenCode присылает тот же запрос повторно, это та же дельта с той же пометкой.
  - Пакет ввода в курс дела заново не отправляется.

### 6.3. Перевод запроса в сообщение ChatGPT

Первое сообщение нового чата содержит:
1. **Правила шлюза.**
   - Ты работаешь как модель агента. Инструменты выполняет программа пользователя.
   - Чтобы вызвать инструменты, ответь одним fenced-блоком `tool_calls` с JSON-массивом
     `[{"name": "...", "arguments": {...}}]`. Перед блоком можно написать короткий текст.
   - Без блока ответ считается окончательным текстом для пользователя.
   - Несколько вызовов в одном блоке допустимы.
   - Не используй Canvas, не вызывай свои встроенные инструменты ChatGPT.
2. **Системная подсказка OpenCode** — как есть.
3. **Инструменты:** имя, описание и компактная схема параметров. Схема без лишних полей,
   только имена, типы, обязательность и `enum`.
4. **История и задача пользователя.**

Последующие сообщения:
- результаты инструментов в виде `[результат <id> · <имя>]` и текст результата;
- новые сообщения пользователя;
- в конце — короткое напоминание о формате ответа.

Предел одного сообщения в ChatGPT — 150 000 символов. Живая проверка 26.10.2026 на Mac:
сообщения до 450 000 символов доходят целиком, ChatGPT читает их до конца; ввод 450 000
символов занимает около 100 с. Предел взят с запасом, чтобы ввод одного сообщения оставался
в пределах 30–40 с. Если длиннее, шлюз делит сообщение на части «часть N из M, ответь словом ok». Ответы на
промежуточные части не разбираются.

### 6.4. Перевод ответа ChatGPT обратно

- **Есть ровно один блок `tool_calls`** с корректным JSON. Шлюз проверяет:
  - каждое имя есть среди инструментов запроса;
  - обязательные параметры на месте, на любой глубине схемы (вложенные объекты, элементы
    массивов `items`);
  - типы совпадают со схемой, массивы не короче `minItems`; ошибка вложенного поля называет его
    путь (`questions[0].options[1].description: нет обязательного поля`). Ключи, которых нет в
    схеме с `additionalProperties: false`, и `null` для необязательных полей молча отбрасываются
    (что OpenCode такие ключи и сам игнорирует — вывод, а не наблюдение: схемы Effect по
    умолчанию отбрасывают лишние ключи, и в живом прогоне 3 OpenCode не отклонил ни одного
    вызова).

  Разметка `<CodeBlock language="X">…</CodeBlock>`, которую поток ChatGPT иногда отдаёт вместо
  fenced-блока, читается как блок с меткой X (нужен атрибут `language`; сущности HTML в теле
  раскодируются, только если тело выглядит экранированным). Автоссылки `[U](U)` на http(s)-адрес
  в строках аргументов читаются как `U`.

  Затем отдаёт `tool_calls` с новыми id (`call_<сессия>_<n>`) и текстом до блока в `content`.
- **Блока нет** — ответ — это текст, `finish_reason: "stop"`.
- **Блок есть, но неверный** (не JSON, неизвестный инструмент, нет обязательного параметра,
  два блока) — одна автоматическая просьба исправить с объяснением ошибки. Если не помогло,
  OpenCode получает текст с объяснением проблемы, и пользователь видит его.
- **`usage`** — оценка: символы / 4.

### 6.5. Безопасность в шлюзе

- **Вычистка секретов** (`core::redact`) ко всему, что уходит в ChatGPT: системная подсказка,
  сообщения пользователя, результаты инструментов. Сначала вычистка, потом деление на части.
- **Denylist для `shell`.** Если команда в вызове `shell` получает `Blocked`, вызов не отдаётся
  OpenCode. ChatGPT получает «команда запрещена правилами: <правило>; предложи другой способ»
  (один раз за ход). Повторный запрещённый вызов превращается в текст для пользователя.
  Подтверждения остальных команд — дело OpenCode и его разрешений.
- **Маркер вычищенного секрета.** Вызов `patch` (или другого инструмента записи), в аргументах
  которого есть маркер вычищенного секрета, не отдаётся OpenCode. ChatGPT получает просьбу не
  переписывать строки с маркером: он видит только маркер и затёр бы настоящий секрет.
- **`execute` по умолчанию не показывается ChatGPT (моё решение).** Шлюз убирает его из списка
  инструментов: код внутри него denylist не видит. Включается параметром `allow_tools` в
  конфиге шлюза. Минус: без `execute` недоступны MCP-инструменты, если пользователь их
  настроит.
- `webfetch` и `websearch` проходят как есть.
- Denylist применяется к любому инструменту, у которого есть строковый параметр `command`, а не
  только к `shell`: на Windows инструмент может называться иначе.

### 6.6. Побочные запросы

- **Заголовок сессии.** В конфиге OpenCode `small_model` указывает на `cgpt/local-title`. Шлюз
  отвечает на него локально: первые 6–8 слов первого сообщения пользователя. В ChatGPT запрос
  не уходит.
- **Подагенты** (`subagent`). Дочерняя сессия OpenCode приходит как новая история и получает
  свой чат по правилу 6.2. Если родитель ждёт подагента, очередь обслуживает подагента, потом
  родителя. Фоновые подагенты (`background: true`) работают, но строго по очереди.

## 7. Мост: что доработать

Нужно до шлюза, иначе сессии смешаются в одном чате:

1. **Своя вкладка для шлюза (моё решение).**
   - Расширение открывает отдельную вкладку chatgpt.com в отдельном окне Chrome, не забирая
     фокус, и пишет в неё все запросы с адресом цели. Вкладки пользователя не трогаются.
   - Окно можно свернуть: ответ берётся из потока, перехват работает и в скрытой вкладке —
     проверено 23.10.
   - Запросы без цели (CLI `cgpt ask` / `cgpt agent`) по-прежнему идут в активную вкладку
     пользователя.
2. **Адресация:**
   - `ask` с целью «в чат по адресу» или «в новый чат»;
   - ответ возвращает адрес чата: временный `/c/local-chatgpt:…` заменяется настоящим после
     ответа;
   - перед отправкой расширение проверяет, что вкладка показывает нужный чат, и переходит в
     него ссылкой без полной загрузки;
   - новый чат открывается действием «Новый чат» в интерфейсе (около 1 запроса к сайту против
     45 при полной загрузке).
3. **`stop`** — остановить генерацию в своей вкладке.
4. **`status`** — есть ли расширение, вкладка, вход в аккаунт.
5. **`rate_limited`** — распознать сообщение ChatGPT об ограничении частоты и вернуть отдельный
   код. Шлюз ставит паузу 5 минут, при повторе за час — 15, затем 30. Во время паузы — сразу 429.
6. **Транспорт на Windows.** Хост и клиенты (шлюз, CLI) общаются через named pipe
   `\\.\pipe\cgpt-bridge-<user>`, на macOS и Linux — через Unix-сокет, как сейчас. Например,
   через крейт `interprocess` (новая зависимость).

## 8. Установка на Windows и macOS

Решение пользователя (26.10.2026): всё должно работать и на Mac, не только на Windows. Mac — такая
же целевая платформа.

**macOS:**
- Архив `cgpt-bridge-<версия>-macos-<arch>.tar.gz`. Внутри:
  - `cgpt-gateway`, `cgpt-bridge-host`, `cgpt`;
  - папка расширения;
  - скрипт `install.sh`.
- `install.sh`:
  - кладёт файлы в `~/Library/Application Support/cgpt-bridge/`;
  - регистрирует хост в Chrome (манифест в `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/`);
  - создаёт конфиг шлюза (`~/Library/Application Support/cgpt-gateway/config.json`) с токеном;
  - добавляет провайдер `cgpt` в глобальный конфиг OpenCode (копия перед изменением);
  - ставит шлюз в автозапуск через LaunchAgent (`~/Library/LaunchAgents/com.cgpt-bridge.gateway.plist`) и запускает его.
- `uninstall.sh` убирает своё и не трогает чужое.
- В CI собирается и проверяется на `macos-latest`.

**Windows:**

- Архив или установщик для одного пользователя, без прав администратора. Внутри:
  - `cgpt-gateway.exe`, `cgpt-bridge-host.exe`;
  - папка расширения;
  - скрипт `install.ps1`.
- `install.ps1`:
  - кладёт файлы в `%LOCALAPPDATA%\cgpt-bridge\`;
  - регистрирует хост в Chrome через ключ HKCU и манифест;
  - создаёт конфиг шлюза с токеном;
  - добавляет в глобальный конфиг OpenCode (`~/.config/opencode/opencode.json`) провайдер
    `cgpt` с `chatgpt-web` и `local-title`. Остальное в конфиге не трогается, перед изменением
    делается копия;
  - ставит шлюз в автозапуск при входе (значение `cgpt-gateway` в `HKCU\...\CurrentVersion\Run`; ярлык `Startup` не подходит: WScript.Shell не сохраняет путь вне ANSI-кодовой страницы) и запускает его.
- Расширение загружается вручную по подсказке.
- Сам OpenCode пользователь ставит отдельно (официальный установщик).
- В CI (`windows-latest`) собираются бинарники и архив.

## 9. Проверка

- **Unit- и интеграционные тесты шлюза** на поддельном хосте:
  - перевод запроса и ответа;
  - сессии и отпечатки;
  - деление на части;
  - разбор `tool_calls`, просьба исправить;
  - денайлист и маркер;
  - заголовок локально;
  - токен и порт;
  - SSE-формат.
- **Живая проверка на Mac:** OpenCode + шлюз + мост на учебном проекте. Нужно пройти чтение,
  поиск, правку `patch`, команду, вопрос `question`, скилл, подагента, «Стоп» в OpenCode и две
  сессии параллельно.
- **CI на Windows** — сборка и тесты named pipe.
- **Приёмка** — у пользователя дома по критерию из раздела 2, а также установка из архива и
  короткий прогон на Mac.

## 10. Риски

| Риск | Что делаем |
|---|---|
| ChatGPT плохо держит формат `tool_calls` | Живая проверка — первая крупная веха плана. Порог (моё решение): из не меньше чем 20 ходов с инструментами 90% разбираются без просьбы исправить и 98% — с ней. Не прошли — работа останавливается и сообщается пользователю с цифрами; запасной формат обсуждается тогда же. Одна просьба исправить за ход; правила формата повторяются в каждом сообщении |
| Длинная подсказка OpenCode (около 30 000 символов на старте) упирается в предел поля ввода | Подбор предела на живой странице, деление на части |
| Сжатие контекста в OpenCode переписывает историю | Новый чат с пакетом ввода в курс дела (6.2) |
| Разметка ChatGPT меняется | Знание изолировано в адаптере расширения; понятные ошибки 502 |
| Ограничения частоты | Пауза и 429; меньше полных загрузок страницы |
| Локальный порт | Только 127.0.0.1 и токен |
