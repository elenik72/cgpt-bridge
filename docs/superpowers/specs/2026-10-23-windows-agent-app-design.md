# Windows-приложение «агент на веб-ChatGPT» — дизайн MVP

Дата: 23.10.2026. Статус: на согласовании.
Рабочее название приложения: **cgpt-desk** (моё решение, можно поменять).

## 1. Зачем

Пользователь ведёт на домашней Windows-машине проект в Codex: копирует приложение
по своему процессу разработки. В проекте установлены скиллы (`codex-kit`: дирижёр этапов
`dev-process`, superpowers, archify), есть план, макет, часть кода, были ревью и тесты.
Агент задавал вопросы, когда что-то было непонятно.

Нужно приложение с окном, как Claude Code на десктопе. В нём можно:
- вести работу в разных проектах;
- видеть файлы, код и изменения;
- общаться не в консоли.

«Мозг» — **веб-версия ChatGPT** во вкладке Chrome пользователя, через уже работающий мост
cgpt-bridge (расширение Chrome и хост). API OpenAI не используется: работа идёт по подписке
ChatGPT.

Пользователь один — владелец машины. Приложение личное, не продукт.

## 2. Критерий успеха MVP

Стек копируемого приложения неизвестен: Codex выбирал и ставил инструменты по ходу. Поэтому
MVP не опирается на конкретный стек и закладывает установку инструментов, сборку, запуск
приложения или dev-сервера и проверку глазами пользователя (8.5).


ChatGPT в приложении **доводит до конца один этап плана** в проекте с копированием
приложения на домашней Windows-машине. Он продолжает работу, начатую в Codex, опираясь на
файлы проекта: инструкции, план, скиллы. Это включает:
- чтение кода;
- правки;
- запуск тестов и сборки;
- вопросы пользователю.

## 3. Цели, не-цели, анти-цели

**Цели**
- Опыт работы как в Claude Code: переписка, карточки действий, подтверждения, план, правая
  панель с изменениями, файлами и выводом команд.
- Совместимость с настройкой Codex пользователя без переноса файлов: те же `AGENTS.md` и скиллы.
- Несколько проектов. Сессии сохраняются, и их можно продолжить.
- Работа на обычной Windows, команды выполняются в PowerShell.

**Не-цели MVP** (позже или никогда)
- Несколько сессий одновременно: в работе всегда одна, остальные ждут.
- Отдельные агенты-помощники (ревьюер, исследователь).
- MCP-канал через туннель. Решено остаться на браузерном пути.
- Картинки и файлы во вложениях к сообщениям ChatGPT.
- Работа с git через интерфейс: git только командами.
- Интерактивный терминал: панель показывает только вывод команд агента.
- Автообновление, подписанный установщик, публикация в магазинах.
- Подхват истории переписки Codex: продолжение опирается на файлы проекта.
- Выбор модели ChatGPT из приложения: используется модель, выбранная во вкладке.

**Анти-цели** — провал, даже если всё «работает»:
- Сообщение молча уходит не в тот чат ChatGPT.
- Команда или правка выполняется так, что пользователь этого не видит и не может проследить.
- Приложение читает, выгружает или анализирует историю чатов ChatGPT.
- Секреты из проекта или вывода команд уходят в ChatGPT.
- Обычная работа пользователя с ChatGPT в браузере ломается: мост действует только во время
  запроса (это уже так после правок 23.10).
- Нужен API-ключ или платный доступ сверх подписки.

## 4. Ограничения

- Windows 10/11, Google Chrome, пользователь залогинен в ChatGPT.
- Транспорт к ChatGPT — Chrome Native Messaging, без локальных HTTP- и WebSocket-портов.
  Это правило cgpt-bridge, оно сохраняется.
- Ход через браузер занимает 5–10 секунд и больше, если модель думает. ChatGPT ограничивает
  частоту **запросов** к сайту (а не сообщений), поэтому число ходов и перезагрузок страницы
  нужно беречь.
- Разметка ChatGPT меняется без предупреждения. Знание о ней изолировано в адаптере
  расширения (`extension/src/chatgptAdapter.ts`, `sseParser.ts`).
- Риск для аккаунта: управление веб-интерфейсом программой может противоречить условиям
  использования OpenAI. Пользователь знает об этом и принимает риск.

## 5. Решения пользователя

| Вопрос | Решение |
|---|---|
| Кто пользуется | Только пользователь, домашняя Windows-машина |
| Канал к ChatGPT | Браузерный (cgpt-bridge), не MCP-коннектор |
| Интерфейс | Вариант A: три колонки — проекты и сессии · переписка · правая панель с вкладками «Изменения», «Файлы», «Терминал» |
| Самостоятельность | Как в Claude Code: режимы «Обычный», «Принимать правки», «План», «Без подтверждений» |
| Одновременность | Одна сессия в работе за раз |
| Состав MVP | Раздел 7 согласован целиком, включая «Новый чат с передачей контекста» и ревью кода через скилл |

## 6. Архитектура

```
┌──────────────── cgpt-desk (Tauri 2) ─────────────────┐
│  UI: React + TypeScript                              │
│   проекты/сессии · переписка · правая панель         │
│            ▲ события        │ команды пользователя   │
│            │                ▼                        │
│  Ядро (Rust):                                        │
│   цикл агента · протокол v2 · инструменты            │
│   (файлы, поиск, PowerShell) · разрешения ·          │
│   denylist · вычистка секретов · хранилище сессий    │
└───────────────┬──────────────────────────────────────┘
                │ named pipe \\.\pipe\cgpt-bridge-<user>
                ▼
   cgpt-bridge-host (Rust; запускает Chrome)
                │ stdio, Native Messaging
                ▼
   Расширение Chrome: service worker → content script
   → chatgptAdapter + pageShim (перехват SSE) → вкладка chatgpt.com
```

**Репозиторий.** Всё живёт в `bambella667/cgpt-bridge` (моё решение). Новые части:
- `app/` — проект Tauri;
- `core/` — общий Rust-крейт, в который из `cli/` выносятся denylist, вычистка секретов,
  запуск команд и хранилище. Им пользуются и приложение, и CLI;
- `protocol/` расширяется.

CLI `cgpt` продолжает работать.

**Хост.** Переходит с Unix-сокета на кроссплатформенный локальный сокет: named pipe на Windows,
Unix-сокет на macOS и Linux. Например, через крейт `interprocess`; это новая зависимость.
Хост остаётся тонким передатчиком. Ему нужны новые типы запросов:
- `ask` с адресом цели: «в этот чат» (`conversation_url`) или «в новый чат»;
- `stop` — остановить генерацию в целевой вкладке;
- `status` — есть ли расширение, есть ли вкладка ChatGPT, какой чат открыт;
- `diagnose` — отчёт адаптера о разметке.

**Расширение.**
- **Своя вкладка (моё решение).** Приложение работает в отдельной вкладке ChatGPT, которую
  открывает само при первом запросе: одна полная загрузка, около 45 запросов, один раз за
  запуск приложения. Вкладки пользователя мост не трогает. Расширение помечает свою вкладку
  (запоминает её id) и пишет только туда. Если в ней перешли на другой чат, перед отправкой
  возвращается к чату сессии переходом по ссылке, без полной загрузки. Если вкладку закрыли,
  открывает новую. Смотреть в неё можно, писать руками не нужно — это видно по пометке в
  заголовке вкладки.
- Учится открывать новый чат: клиентским переходом приложения, а не полной загрузкой
  chatgpt.com. Полная загрузка — около 45 запросов, новый чат в интерфейсе — 1 (данные
  chatgpt-use).
- Учится писать в конкретный чат по адресу.
- Проверяет, что вкладка показывает нужный чат, прежде чем отправлять.
- Распознаёт сообщение ChatGPT об ограничении частоты запросов и возвращает отдельный код
  ошибки `rate_limited`.

**Ядро и UI.**
- Ядро ведёт цикл агента и шлёт в UI события: новое сообщение, действие ждёт решения,
  действие выполнено, ход ChatGPT начался или закончился, сменилось состояние связи.
- UI отправляет в ядро решения пользователя, новые сообщения, «Стоп» и смену режима.

## 7. Состав MVP

### 7.1. Проекты и сессии

- **Проект** — папка на диске, добавленная кнопкой «Открыть папку…». Список проектов слева.
- **Сессия** — одна переписка, привязанная к одному чату ChatGPT. Адрес чата (`/c/<id>`)
  запоминается после первого ответа; до этого адрес временный (`/c/local-chatgpt:…`).
  Новая сессия всегда открывает новый чат.
- Сессии хранятся вне проекта, в папке данных приложения (`%APPDATA%\cgpt-desk\`):
  метаданные, журнал событий и исходные версии файлов для отката. Проект ничем не засоряется.
- **Продолжить сессию.** Приложение открывает её чат в ChatGPT и продолжает с того же места.
  Если чат недоступен, предлагает «Новый чат с передачей контекста».
- **Одна сессия в работе за раз.** Пока ChatGPT отвечает или ждёт решения, поле ввода в других
  сессиях заблокировано с пояснением. Читать и смотреть их можно.

### 7.2. Ввод в курс дела (первое сообщение сессии)

Приложение собирает и отправляет ChatGPT пакет в таком порядке:

1. **Правила протокола v2** (раздел 8) и правила поведения: отвечать только блоком протокола;
   задавать вопросы через действие «вопрос»; не использовать Canvas.
2. **Окружение:** Windows, PowerShell (версия), корень проекта, текущий режим работы,
   сегодняшняя дата.
3. **Инструкции** по правилам Codex (сверено с документацией Codex 23.10.2026):
   - глобальные: `%CODEX_HOME%` или `~/.codex` — `AGENTS.override.md`, если есть, иначе
     `AGENTS.md`;
   - проектные: от корня git-репозитория вниз до папки проекта, в каждой папке один файл
     (`AGENTS.override.md`, иначе `AGENTS.md`). Склеиваются от корня к папке проекта. Общий
     предел — 32 КиБ, как у Codex.
4. **Список скиллов:** имя, описание из frontmatter `SKILL.md` и путь. Только список — полный
   текст скилла ChatGPT читает отдельным действием, когда решит его применить. Где искать:
   - `.agents/skills` в каждой папке от проекта до корня репозитория;
   - `~/.agents/skills`;
   - `~/.codex/skills` — Codex его читает по наблюдениям, документация этого не обещает;
   - дополнительные пути из настроек приложения.

   Если `allow_implicit_invocation: false` в `agents/openai.yaml`, скилл помечается как
   «только по явной просьбе».
5. **Задача пользователя.**

Если пакет больше предела одного сообщения, инструкции и список скиллов уходят первыми, а
задача — вторым сообщением. Предел — раздел 8.4.

### 7.3. Переписка и карточки действий

- Сообщения пользователя и текст ChatGPT (поле `message` протокола) отображаются как markdown.
- Каждое действие — карточка:
  - чтение, список папки и поиск сворачиваются в строку «Прочитал N файлов» с раскрытием;
  - правка показывает файл, счётчик «+N −M» и разницу «было/стало» в правой панели;
  - команда показывает текст команды, папку, таймаут, риск по оценке ChatGPT и по оценке
    приложения;
  - вопрос — жёлтая карточка: текст вопроса, варианты кнопками и поле «Свой ответ».
- Во время хода ChatGPT виден индикатор «ChatGPT отвечает…» со временем ожидания.
  Показ текста по мере генерации — по возможности (оставлено строителю, раздел 13).
- **«Стоп»** прерывает генерацию в ChatGPT и останавливает цикл. Уже выполненное не
  откатывается.

### 7.4. План

ChatGPT обновляет список шагов действием `update_plan`. Список виден над полем ввода, текущий
шаг выделен. В режиме «План» ChatGPT только читает и в конце предлагает план. Кнопка
«Утвердить план» переводит сессию в «Обычный» режим и отправляет ChatGPT «план утверждён,
выполняй».

### 7.5. Режимы и разрешения

| Режим | Чтение, поиск | Правки файлов | Команды |
|---|---|---|---|
| Обычный (по умолчанию) | сами | спрашивать | «только чтение» сами, остальные спрашивать |
| Принимать правки | сами | сами (видны в «Изменениях») | «только чтение» сами, остальные спрашивать |
| План | сами | запрещены | только «только чтение», сами; остальные отклоняются |
| Без подтверждений | сами | сами | сами, кроме заблокированного; режим помечен красным |

«Только чтение» (моё решение) — встроенный неизменяемый список, расширение классификатора
cgpt-bridge: `Get-ChildItem`, `Get-Content`, `Select-String`, `Test-Path`, `Get-Location`,
`git status|log|diff|show|branch`, `dir`, `type`, `where`, версии инструментов
(`node -v`, `dotnet --version` и т. п.), без перенаправления в файл и без конвейера в
изменяющие команды. Пользователь расширяет его своими правилами «Разрешить всегда».

Правила, действующие во всех режимах:
- **Кнопки на карточке:** «Разрешить», «Разрешить всегда», «Отклонить». Отклонение уходит
  ChatGPT как результат с пояснением, можно приписать причину.
- **«Разрешить всегда» для команды** запоминает правило для проекта по началу команды,
  например `npm test`. Для правки предлагает переключиться в «Принимать правки». Правила
  хранятся в данных приложения и видны и удаляются в настройках проекта.
- **Запреты, которые не снимаются ни режимом, ни правилом:**
  - denylist из cgpt-bridge, дополненный командами PowerShell и cmd: рекурсивное удаление
    корня диска или профиля, `format`, `reg delete HKLM`, `Set-ExecutionPolicy`, загрузка с
    исполнением (`iwr … | iex`), чтение `.ssh`, `.aws`, профиля Chrome, `cmdkey`,
    `vssadmin delete shadows`, `bcdedit`;
  - выход за папку проекта для записи и для рабочей папки команд, с учётом `..`, ссылок,
    регистра и `\\?\`. Граница — открытая папка проекта, а не корень git-репозитория
    (моё решение);
  - **исключение только для чтения (моё решение):** `read_file`, `list_dir` и `read_skill`
    могут читать папки скиллов из 7.2 и файлы `AGENTS.md`, найденные по пути к корню
    репозитория. Скрипты скиллов можно запускать командой с рабочей папкой внутри проекта и
    только с подтверждением в любом режиме, кроме «Без подтверждений»;
  - запись в `.git/`.
- **Вычистка секретов** из любого вывода и содержимого файлов до отправки в ChatGPT — как в
  cgpt-bridge: сначала вычистка, потом обрезка.

### 7.6. Правая панель (вариант A)

- **«Изменения».** Файлы, изменённые в этой сессии, с разницей «было/стало» относительно
  состояния до сессии. «Откатить» по файлу возвращает исходную версию. Если файл изменили со
  стороны, сначала предупреждение.
  - **Правки ChatGPT** (`edit_file`, `write_file`) — с исходной версией и откатом.
  - **Изменения от команд (моё решение).** Если проект в git, после каждой команды приложение
    сверяет `git status` с состоянием до неё и показывает изменённые командой файлы отдельной
    группой «Изменено командой» с разницей от git, без отката из приложения. Если проект не в
    git — только список «команда могла изменить файлы» в карточке команды. Снимков и слежения
    за всей папкой в MVP нет.
- **«Файлы».** Дерево проекта без `.gitignore`-исключённого и просмотр файла только для чтения,
  с подсветкой синтаксиса.
- **«Терминал».** Вывод команд, которые запускал ChatGPT в этой сессии: команда, код
  завершения, время, вывод. Не интерактивный.

### 7.7. Новый чат с передачей контекста

Кнопка в шапке сессии. Приложение предлагает её само, когда объём переписки в чате переходит
порог (подбирается строителем, раздел 13). Как работает:
1. ChatGPT в текущем чате пишет сводку по шаблону: цель, что сделано, текущий шаг плана,
   изменённые файлы, открытые вопросы, договорённости.
2. Приложение открывает новый чат и отправляет пакет из 7.2 со сводкой вместо задачи.
3. Сессия продолжается в новом чате, старый адрес сохраняется в истории.

### 7.8. Ревью кода

Отдельного агента нет. Ревью — обычная просьба к ChatGPT в сессии. Например, «проведи ревью
по скиллу requesting-code-review»: ChatGPT читает скилл, изменения и код и отвечает
результатом. Особой поддержки в приложении не требуется.

### 7.9. Связь и надёжность

- **Строка состояния** над перепиской: «ChatGPT подключён · вкладка “<название чата>”», либо
  причина, почему нет (нет расширения, нет вкладки, нужно войти, ограничение частоты).
- **Конец ответа** берётся из потока по `end_turn`, а не из «тишины» на странице. Так уже
  устроено в расширении после правок 23.10.
- **Ограничение частоты запросов:** пауза 5 минут, при повторе в течение часа — 15, затем 30
  (подход chatgpt-use). Во время паузы виден таймер, отправка заблокирована.
- **Обрыв посреди хода** (закрыли вкладку, перезагрузили расширение): приложение не шлёт
  сообщение повторно вслепую. Оно предлагает «Проверить ответ в чате»: открыть чат и забрать
  последний ответ, если он есть. Иначе — «Отправить заново».
- **Нарушение протокола** (нет блока или блок неверный): одна автоматическая просьба исправить
  ответ. Если не помогло, сессия останавливается с понятным сообщением и кнопкой «Повторить».

### 7.10. Установка на Windows

- Установщик NSIS от Tauri, для одного пользователя, без прав администратора. Ставит
  приложение и хост в `%LOCALAPPDATA%\cgpt-desk\`, пишет манифест Native Messaging и ключ
  `HKCU\Software\Google\Chrome\NativeMessagingHosts\com.cgpt_bridge.host`.
- Расширение загружается вручную («Загрузить распакованное» из папки установки).
  Приложение показывает пошаговую подсказку, пока не увидит расширение.
- Установщик не подписан. Windows SmartScreen предупредит при первом запуске, это допустимо.

## 8. Протокол действий v2

### 8.1. Ответ ChatGPT

Ровно один fenced-блок `cgpt-agent-v2` с JSON. Всё вне блока игнорируется:

```cgpt-agent-v2
{
  "version": 2,
  "status": "continue | ask | final",
  "message": "markdown для пользователя",
  "plan": [{"id": "1", "text": "…", "status": "pending|doing|done"}],
  "actions": [ { "id": "a1", "type": "read_file", "path": "src/app.ts", "offset": 1, "limit": 600 } ]
}
```

Типы действий:

| type | Поля | Смысл |
|---|---|---|
| `list_dir` | `path`, `depth` | Содержимое папки, `.gitignore` учитывается |
| `read_file` | `path`, `offset`, `limit` | Окно файла: до 600 строк и до 30 000 символов, с номерами строк и указанием, откуда читать дальше |
| `search` | `pattern`, `path`, `glob`, `regex` | Поиск по коду внутри приложения, без внешних программ. До 200 совпадений с путём и номером строки |
| `read_skill` | `name` | Полный текст `SKILL.md` по имени из списка, плюс список файлов скилла |
| `edit_file` | `path`, `edits: [{old, new, replace_all}]` | Точная замена фрагментов. `old` должен встречаться ровно один раз, если не задан `replace_all` |
| `write_file` | `path`, `content`, `overwrite` | Создать файл. Перезапись существующего — только при `overwrite: true` |
| `run_command` | `command`, `cwd`, `timeout_ms`, `risk`, `description` | PowerShell-команда |
| `start_process` | `command`, `cwd`, `name`, `ready_pattern`, `description` | Запустить долгоживущий процесс (dev-сервер, собранное приложение, watcher) и оставить работать. Возвращает первые строки вывода, а при заданном `ready_pattern` ждёт его появления, но не дольше 60 с |
| `process_output` | `name`, `tail` | Последние строки вывода фонового процесса и его состояние (работает / завершился с кодом) |
| `stop_process` | `name` | Остановить фоновый процесс со всем деревом |
| `ask_user` | `question`, `options[]`, `allow_free_text` | Вопрос пользователю |
| `update_plan` | — (используется поле `plan`) | Обновить план |

### 8.2. Правила хода

- В одном ходе можно сколько угодно действий чтения (`list_dir`, `read_file`, `search`,
  `read_skill`, `process_output`), но не больше 8, и **не больше одного изменяющего действия**
  (`edit_file`, `write_file`, `run_command`, `start_process` или `stop_process`). Изменяющее выполняется после чтений (моё решение: меньше
  ходов, но каждое изменение отдельно видно и подтверждается).
- `ask_user` — только одно действие в ходе, со `status: "ask"`.
- `status: "final"` — без действий: работа по задаче закончена, `message` — итог.
- ChatGPT `risk` — подсказка. Приложение оценивает риск само и показывает обе оценки.

### 8.3. Ответ приложения

Один fenced-блок `cgpt-result-v2` с результатами по `id` действий:
- для каждого действия — `ok`, `error` или `rejected`, плюс данные;
- для команды — код завершения, время, `stdout` и `stderr` после вычистки секретов и обрезки;
- для отклонения — причина пользователя, если указана;
- новое сообщение пользователя, если он написал его, пока шёл ход.

### 8.4. Пределы

- Вывод одного действия, кроме `read_file`, — до 20 000 символов, с пометкой, как сузить запрос.
- Одно сообщение в ChatGPT — до 60 000 символов (моя оценка). Строитель проверяет реальный
  предел вставки в поле ввода ChatGPT и подбирает значение (раздел 13). При превышении
  результаты делятся на несколько сообщений или сокращаются с пометкой.
- `timeout_ms` команды — по умолчанию 120 000, не больше 600 000. Больше — урезается с
  предупреждением.

### 8.5. Запуск команд в Windows

- `pwsh -NoLogo -NoProfile -NonInteractive -Command <cmd>`, если PowerShell 7 есть, иначе
  `powershell.exe` с теми же флагами.
- Вывод в UTF-8: перед командой выставляется кодировка консоли.
- Рабочая папка — внутри проекта.
- Процесс запускается в Job Object: по таймауту или «Стоп» завершается всё дерево процессов.
- Ввод команды закрыт (stdin = null). Команды, которые ждут ввода, завершаются по таймауту.
- **Установка инструментов.** Этапу может понадобиться ставить SDK, пакеты и утилиты по ходу:
  `winget`, `npm`, `dotnet`, `pip` и т. п. Codex у пользователя делал так же. Такие команды
  никогда не считаются «только чтением». Для них ChatGPT может запросить `timeout_ms` до
  1 800 000 (30 минут); выше 600 000 — только с подтверждением, даже в режиме «Без
  подтверждений». Если установка требует прав администратора, Windows покажет окно UAC:
  приложение пишет в карточке «ждём подтверждения Windows» и не пытается его обойти.
- **Фоновые процессы** (`start_process`):
  - запускаются в своём Job Object;
  - привязаны к сессии и останавливаются по `stop_process`, по «Стоп» всей сессии, при
    закрытии сессии или приложения;
  - вывод копится в кольцевом буфере (последние 2 000 строк) и виден во вкладке «Терминал»
    отдельной строкой на процесс, с кнопкой «Остановить»;
  - одновременно не больше 3 на сессию;
  - запуск требует подтверждения в режимах «Обычный» и «Принимать правки»; в режиме «План»
    запрещён.
- **Проверка результата глазами.** ChatGPT не видит окно запущенного приложения: картинки во
  вложениях вне MVP. Визуальная проверка — вопрос пользователю через `ask_user`
  («Открылось ли окно? Видна ли таблица?»), ответ кнопками или текстом. Так в MVP закрывается
  этап «собрать, запустить, проверить».

## 9. Хранение

- `%APPDATA%\cgpt-desk\projects.json` — список проектов.
- `%APPDATA%\cgpt-desk\projects\<id>\`:
  - `rules.json` — разрешения «всегда»;
  - `sessions\<id>\meta.json` — чат(ы), режим, состояние;
  - `sessions\<id>\events.jsonl` — журнал событий, источник истины для отображения
    переписки. Тексты хранятся после вычистки секретов;
  - `sessions\<id>\originals\` — исходные версии изменённых файлов для отката.
- После любого сбоя журнал читается построчно.

## 10. Разработка и проверка

- Tauri кроссплатформенный. Приложение разрабатывается и проверяется на Mac пользователя
  с живым мостом: Chrome, ChatGPT, расширение. Так было проверено и 23.10.
- **Mac — площадка разработки, а не целевая платформа (моё решение).** Ядро выбирает оболочку
  по ОС: PowerShell на Windows, `$SHELL` на macOS (как в CLI cgpt). ChatGPT всегда сообщается
  настоящая ОС и оболочка. Denylist и пути проверяются на обеих ОС, установщик делается только
  для Windows. Полный прогон на Mac доказывает работу интерфейса, цикла агента и моста, но не
  частей для Windows.
- Перед приёмкой — прогон на Mac на учебной задаче полного цикла: создать небольшое
  приложение с нуля по скиллу `dev-process`, поставить зависимости, собрать, запустить
  фоновым процессом, ответить на вопрос о проверке. Так проверяется всё, кроме частей для
  Windows.
- Части только для Windows проверяются в CI на `windows-latest` (unit- и интеграционные
  тесты): named pipe, PowerShell, Job Object, пути `\\?\`, реестр в установщике. CI собирает
  установщик NSIS как артефакт.
- **Приёмка** — у пользователя дома: установка, подключение расширения, один этап плана в
  проекте с копированием приложения (раздел 2).
- Тесты: протокол (разбор, проверка, ремонт), инструменты (чтение окнами, замена, поиск,
  границы проекта), denylist для PowerShell, вычистка секретов, хранилище, цикл агента на
  поддельном хосте. UI — без автотестов в MVP, проверка руками и скриншотами.

## 12. Риски

| Риск | Что делаем |
|---|---|
| ChatGPT меняет разметку или поток | Знание изолировано в адаптере; `diagnose` и понятная ошибка `dom_failure` вместо таймаута; есть скрипт проверки разметки |
| ChatGPT не соблюдает протокол | Строгая проверка, одна просьба исправить, остановка с сообщением; правила протокола напоминаются в конце каждого результата |
| Ограничения частоты запросов | Пачки чтений в одном ходе, без перезагрузок страницы, паузы |
| Длинные сессии упираются в контекст ChatGPT | «Новый чат с передачей контекста» |
| Части для Windows нельзя проверить на Mac | CI на Windows; приёмка у пользователя |
| Блокировка аккаунта за автоматизацию | Принято пользователем; мост действует только во время запроса, частота ходов умеренная |

## 13. Оставлено строителю

- Библиотеки UI (компоненты, просмотр кода, показ разницы), если подходят по лицензии
  (MIT, Apache, BSD) и выглядят аккуратно в светлой и тёмной теме Windows.
- Показ текста ChatGPT по мере генерации — по возможности. Минимум: индикатор и время ожидания.
- Порог предложения «Нового чата с передачей контекста» и шаблон сводки.
- Реальный предел длины одного сообщения в ChatGPT и разбиение больших результатов.
- Точная разметка кнопки «Новый чат» и перехода в чат по адресу — сверить на живой странице.
- Название приложения и иконка.
- Структура крейтов внутри `core/` и как CLI переходит на них — без изменения поведения CLI.
